# 扩展到写字楼与应急场景（未来方向，非当前范围）

日期：2026-09-12
状态：**仅记录想法，未纳入当前计划，未承诺实现**
提出人：用户

## 原始想法

> 假如我在一个写字楼里面，我通过大模型可以识别人物、记录人的位置，那当火灾发生之后，非常适合救援（虽然和语音没啥关系）。

## 为什么值得记下来

这个想法触到了当前设计里一个真实的、可复用的核心：**权威位置状态 + 可查询接口 + 不撒谎的状态语义**。当前 v1 虽然只做三个房间的虚拟住宅，但"人物位置由状态服务持有、摄像机观察不覆盖模拟位置、临时轨迹丢失要解除绑定"这些约束，恰好是应急场景最需要的东西。

## 与当前 v1 的差异（诚实评估）

| 维度 | 当前 v1 | 写字楼应急场景 |
| --- | --- | --- |
| 空间规模 | 3 个房间、单机 | 多楼层、多区域、多摄像头 |
| 位置来源 | **手动模拟** | 必须真实多摄像头跟踪 |
| 身份 | **手动绑定**，不做识别 | 需要可靠身份或至少稳定轨迹 |
| 人物规模 | 3 人 | 数十到数百人 |
| 时效要求 | 秒级休闲 | 秒级且**误报代价极高** |
| 失效模式 | 播报失败 | 掉线、遮挡、跨摄像头交接错误 |
| 合规 | 家庭内部 | 员工隐私、消防法规、责任归属 |

**关键结论**：当前 v1 的架构方向可复用，但**数据来源必须从"手动模拟"换成"真实多摄像头"，并且需要跨摄像头轨迹交接与丢失判定**——这正是设计第 2 节明确排除在 v1 之外的能力。因此这不是"顺手加个功能"，而是一个独立项目。

## 若要推进，需要先解决的核心问题

1. **跨摄像头身份与轨迹交接**：同一个人从 A 相机走到 B 相机，如何在没有任何生物特征的情况下确认是同一人？当前设计明确不做人脸/声纹，这个前提在此场景下需要重新讨论。
2. **置信度与不确定性的表达**：救援场景绝不能把"可能"说成"确定"。当前设计里的 `检测置信度不是身份置信度` 这条原则必须升级成更严格的措辞约束。
3. **时间戳与新鲜度**：位置必须有明确的有效期。"5 分钟前在 3 楼"和"现在在 3 楼"对救援意义完全不同。当前 `VisualObservation.observed_at_ms` 已有字段，但缺少过期与陈旧度语义。
4. **降级路径**：摄像头掉线时如何如实报告"未知"而不是保留旧位置当作现状。
5. **隐私与合规**：写字楼场景涉及员工持续定位，法律与伦理审查不可跳过。

## 与智能家居主线的关系

- **共用**：权威状态服务、版本化增量、受限工具接口、诚实状态语义、Unity 展示层。
- **不共用**：语音交互链路（用户自己也指出"和语音没啥关系"）。
- **建议**：等 v1 的虚拟住宅场景跑通（阶段 C/D/E 完成）后，再单独评估是否立项；届时状态服务的接口应能复用，但感知层要重做。

## 现在不动的东西

- 不修改 v1 范围。
- 不为此调整当前阶段划分。
- 不在状态服务里预埋多楼层/多摄像头结构，避免过度设计。
