## 阶段 A：本地语音验证

### A1. 独立环境

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
```

`.venv/` 已在 `.gitignore` 中。**不使用全局 3.13 环境**，避免污染既有项目。

### A2. 运行时与模型核验（先核验再下载）

1. 在 `sherpa-onnx` 官方文档确认 Windows 版本、Python 3.11 wheel 与所需 API 存在。
2. 确认 KWS、Silero VAD、SenseVoice、Kokoro 四个模型的下载地址、文件大小与许可证。
3. 把核验结论写入 `docs/superpowers/notes/` 下的记录文件，包含来源链接与核验日期。
4. **许可证不明确或不允许预期用途的模型不下载。**

### A3. 候选模型（第一阶段）

| 用途 | 候选 | 备注 |
| --- | --- | --- |
| 唤醒 | sherpa-onnx KWS zipformer 中文 3.3M | 可自定义唤醒词，需 token 转换 |
| 端点检测 | Silero VAD | 与 KWS 同一运行时 |
| 识别 | SenseVoiceSmall int8 | 中文为主，CPU 优先 |
| 合成 | Kokoro 中英 v1.1（int8 优先） | 先验证短句播报 |

### A4. 验证脚本与指标

脚本放在 `tools/voice-check/`，只读本地音频文件，不常驻监听：

1. **ASR 准确率**：用同一麦克风实录至少 30 条任务语句（含否定、人名、房间、数字、模糊意图，例如“不要开灯”“有点热”“叫爸爸吃饭”），逐条比对关键信息。
2. **TTS 试听**：至少 20 条家居播报文本，人工确认人名、数字、多音字读音。
3. **唤醒**：至少 20 次主动唤醒，记录成功次数与误触发次数。
4. **负例**：连续播放 30 分钟无意图音频（对话、视频），记录误唤醒与误操作。
5. **延迟与资源**：记录冷启动、热启动的识别耗时、TTS 首次出声、峰值内存。

### A5. 通过门槛（沿用设计文档）

- 30 条语句中关键信息正确 ≥ 27 条。
- 20 次唤醒中 ≥ 18 次成功进入对话。
- 负例中设备误操作 0 次、播报自触发 0 次。
- 不崩溃、不耗尽内存。

未通过时：优先调阈值与设备，其次换候选模型，最后才向用户报告该项不可用并讨论备选方案。

### A6. 产出

`docs/superpowers/reports/2026-09-12-phase-a-voice-report.md`，包含每条语句的实际转写、每项指标、失败案例与结论。

## 阶段 B：家庭状态与受限工具服务

1. 定义数据模型：房间、人物、设备、视觉观察、会话、操作（字段见设计文档第 5 节）。
2. 实现权威状态服务：快照、增量、版本号、重连。
3. 实现六个工具：查询房间、查询人物位置、查询设备状态、设置灯光、设置空调、房间播报。
4. 服务端校验：对象存在、参数范围、房间归属、在线状态、前置版本、操作 ID 去重。
5. 单元测试：目标解析、房间去重、范围校验、版本冲突、操作去重。
6. 集成测试：模拟设备离线、超时、部分成功、重复请求、服务重启。
7. 接口默认绑定 loopback，不开放局域网。

**通过门槛**：上述测试全部通过；离线与冲突路径有对应测试用例。

## 阶段 C：最小 Unity 小屋

1. 新建 Unity 工程（建议 `6000.0.23f1c1`，若第三方包不兼容则退回 2022.3 LTS）。
2. 三个房间、灯、空调、房间播报点；人物用圆点＋名字。
3. 连接状态服务：初始快照、增量同步、断线重连。
4. 拖动人物提交位置；模拟室温由测试面板修改。
5. 语音区、摄像头区、执行记录区界面骨架（摄像头先留空）。
6. 使用单个扬声器按房间播报并高亮目标房间。

**通过门槛**：设计文档「必须通过的场景」第 1、3、4 条在 Unity 中可复现；Unity 1080p 场景 ≥ 30 FPS。

## 阶段 D：云端 Agent 与人物检测

1. 用户选定云端 LLM 厂商并开通 API；设置预算告警与应用侧限额。
2. 密钥写入本地配置（`.env`，已在忽略列表），不进入 Unity 包与日志。
3. 实现 Agent 编排：工具选择、超时、工具轮数上限、澄清状态、操作 ID 复用。
4. 接入语音会话状态机：静音、待机、听取、处理、播报、20 秒退出。
5. 接入本地人物检测与手动身份绑定；轨迹丢失解除绑定。
6. 验证「必须通过的场景」第 2、5、6、8、9、10 条。

**通过门槛**：全部十条场景可复现，含失败与澄清路径。

## 3. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 16 GiB 内存不足 | 模型分批加载；必要时先只跑 ASR＋TTS，再逐步加入检测 |
| 默认麦克风是虚拟设备 | 脚本显式选择 Realtek 物理麦克风；不修改系统默认 |
| 唤醒误触发 | 调整 boosting score 与触发阈值；仍不达标则如实报告 |
| 模型许可证不清 | 停止下载，先核验许可证再决定 |
| Unity 版本兼容 | 优先 6000.0.23f1c1，异常时退回 2022.3.47f1c1 |
| 云端账单超预期 | 厂商预算告警＋应用侧请求数与轮数上限 |
