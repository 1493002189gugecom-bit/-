# 语音 Agent 接入设计

状态：用户已批准，进入实施。

## 1. 目标

让现有语音环从「转写→固定回复」升级为真实家居控制：ASR 转写交给云端 LLM 选择工具，
调用 `home-service` 执行，再用现有 TTS 播报**真实**结果。

本轮只接语言理解与工具调用，不改动唤醒、VAD、ASR、TTS 与播放路径。

## 2. 已确认决策

| 决策 | 选择 |
| --- | --- |
| Agent 大脑 | 云端 LLM 工具调用（DeepSeek，OpenAI 兼容接口） |
| 工具面 | 现有 4 个工具，不做房间播报与人物位置 |
| 集成形式 | 作为 `voice-service` 内部模块，单进程 |
| 显示层 | 无 Unity；命令行与日志 |

## 3. 架构

```text
麦克风 → KWS/VAD → ASR 转写
                    ↓
        agent 模块（voice-service 内）
        - 有限会话上下文
        - 工具面 = home-service 4 个工具
        - 工具循环上限 + 总超时
                    ↓ HTTP 127.0.0.1:8765
            home-service（memory 或 ha 后端）
                    ↓
              TTS 播报（复用现有 playback）
```

## 4. 组件

新增三个扁平模块，沿用目录现有风格：

| 文件 | 职责 | 依赖 |
| --- | --- | --- |
| `src/agent_client.py` | DeepSeek chat completions 与 tool calling 传输层；有界超时与重试；异常不含密钥与响应体 | 仅标准库 |
| `src/agent_tools.py` | 4 个工具的 Schema 与对 `home-service` 的 HTTP 执行 | 仅标准库 |
| `src/agent_session.py` | 编排：上下文、工具循环、澄清承接、空闲退出、诚实措辞 | 上述两者 |

`loop.py` 只改一处：转写后调用 `agent_session`，把返回文本交给现有 TTS。

## 5. 工具契约

| 工具 | 后端 | 说明 |
| --- | --- | --- |
| `query_room_status` | `GET /tool/room_status` | 按房间名或稳定 ID |
| `query_device_status` | `GET /tool/device_status` | 按稳定设备 ID 或房间 |
| `set_light` | `POST /tool/set_light` | `on`、`brightness` 0–100 |
| `set_ac` | `POST /tool/set_ac` | `on`、`mode`、`target_temp` 16–30 |

约束：

- 设备 ID 在 Schema 中是 `enum` 白名单（灯只有 `living_room_light`，空调只有
  `bedroom_ac`），**模型无法发明设备名或路径**。
- 写操作由本地生成 `operation_id`；同一次请求内重试复用同一个 ID。
- 工具循环上限 4 轮，整体时限 20 秒；超限明确失败。

## 6. 诚实措辞规则

写操作的播报文本以 `home-service` 返回的 `phrase` 与错误码为准，**不采用模型的
成功措辞**：

- 任一写操作失败（`ok=false`）：最终文本由工具错误信息构成，**丢弃模型的文本**。
- 全部写操作成功：可使用模型文本；模型文本为空时退回工具 `phrase`。
- 只有查询：使用模型文本，为空时给出结构化摘要。

这样即使模型编造「已经打开了」，也不会被播报出去。

## 7. 错误与故障语义

| 情况 | 行为 |
| --- | --- |
| LLM 不可用/超时/鉴权失败 | 停止本轮，如实播报失败；**不执行新动作** |
| `home-service` 不可达 | 播报后端不可用，不假装已执行 |
| 工具返回 `offline`/`not_found`/`wrong_type` | 按错误码如实播报，禁止声称成功 |
| `confirmation_timeout`/`unconfirmed` | 播报「已提交但未确认」 |
| 循环超限 | 如实播报无法完成，不做猜测动作 |
| 密钥缺失或无效 | 启动即明确失败，不进入语音控制 |
| 空闲 20 秒 / 「没事了」 | 结束会话，清除待澄清与近期目标 |

## 8. 隐私与安全

- 只上传转写文本与必要设备状态，**不上传音频**。
- 密钥只从本地 ignored 文件或环境变量读取；不写入仓库、日志、异常或命令行。
- 历史上下文有界（最近若干轮），不无限增长。

## 9. 测试

**单元（假 LLM + 假 home-service HTTP）**

- 单工具调用、多工具调用、纯闲聊不调用工具。
- 工具循环超限。
- 写操作失败时模型文本被丢弃（防虚假成功）。
- `operation_id` 在同一次请求内复用，不盲目重发。
- LLM 超时/鉴权失败/格式错误分别映射到明确错误码。
- 日志与异常不含密钥。
- 上下文有界；空闲退出清除承接目标。

**真实验收（DeepSeek + 真实 HA 后端）**

1. 「打开客厅灯」→ HA 状态一致。
2. 「客厅灯调到 50」→ 亮度 50。
3. 「有点热」→ 先查室温/空调，再有限调整或追问。
4. 「卧室空调 24 度制冷」→ 已确认。
5. 设备离线 → 如实失败，无成功措辞。
6. 密钥无效 → 明确失败且无设备动作。
7. 日志与提交内容中无密钥。

## 10. 明确不做

- 房间播报、人物位置与空间概念。
- Unity 或任何图形界面。
- 唤醒词、VAD、ASR、TTS 模型或参数的改动。
- 流式 ASR、插话打断、云端音频上传。
- 长期记忆与习惯学习。
